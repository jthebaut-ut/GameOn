Date: 2026-08-09

================================================================================
1. Existing Edit Team logo path reused
================================================================================

Edit Team (`EditFanTeamSheet`) already owns the authoritative pipeline:

- PhotosPicker → loadTransferable(Data) → local `pendingImageData` + `localPreviewImage`
- Preview via `FanTeamMarkView` (local preview overrides remote URLs)
- On Save only:
  - `FanTeamsService.uploadTeamLogo(teamId:imageData:)`
    - bucket: `fan-team-logos`
    - path: `{team_id}/logo-{uuid}.jpg` + companion `_thumb.jpg`
    - compression: `ImageCompression.jpegDataForUpload` presets `.avatar` / `.avatarThumbnail`
  - `FanTeamsService.updateTeamIdentity` → RPC `update_fan_team_identity`
    (`logo_url` / `logo_thumbnail_url`)
  - `FanTeamIdentityChangeCenter.postIdentityChange`
  - `DiscoverMapImageCache` warm for versioned display URLs
  - best-effort Storage cleanup of replaced/removed objects via `MapViewModel`

Create Team now reuses this exact upload + identity-update + cache/realtime path.
No second bucket, path scheme, compression pipeline, or identity RPC.

================================================================================
3. Local pending-image behavior
================================================================================

- Picker selections stay in memory (`pendingImageData` / `localPreviewImage`)
- Changing the photo before Create only replaces local state
- Remove Photo clears local state; fallback mark returns
- Nothing is uploaded until Create succeeds and `team_id` exists
- Policy helper: `FanTeamCreateLogoPolicy.shouldUploadAfterCreate`

================================================================================
4. Create → upload → identity-update sequence
================================================================================

1. `create_fan_team` via `FanTeamsService.createTeam` (logo URLs always nil;
   invitations + Team Chat created by existing RPC)
2. If a final local image is still selected:
   a. `uploadTeamLogo(teamId:imageData:)` → `fan-team-logos/{team_id}/…`
   b. `updateTeamIdentity(... logoURL/logoThumbnailURL ...)`
      with `updateCompetitionLevel: false` (competition already set at create)
   c. post `FanTeamIdentityChange` when My Teams list can resolve conversation id
   d. warm image cache for immediate marks
3. Continue existing `onCreated` → My Teams refresh → open Team Detail

Order preference honored: create Team → logo update → invitation processing already
happened inside create RPC, then logo is attached ASAP for surfaces that refresh.

================================================================================
5. Failure semantics
================================================================================

- Create RPC fails → no upload attempted
- Create succeeds, upload fails → Team kept; friendly warning:
  “Team created, but the photo couldn’t be uploaded. You can add it later.”
  Fallback sport/color mark used
- Upload succeeds, identity update fails → best-effort delete of newly uploaded
  full + thumb objects; same friendly warning; Team kept
- Team is never deleted solely because logo attach failed
