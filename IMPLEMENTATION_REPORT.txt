FANGEO — FAN PROFILE “MESSAGE” BUTTON DID NOT OPEN CHAT

Date: 2026-08-12
No commit. No push. No schema / SQL / notification / friendship / layout changes.

────────────────────────────────────────────────────────────────
1) EXACT ROOT CAUSE
────────────────────────────────────────────────────────────────
Two defects stacked:

A) Data: `messageFriend` called `startDirectConversationWithFriend` (canonical
   RPC) but discarded the returned conversation UUID (`_ = try await …`).
   It then set `chatViewModel.pendingDmOpenPreview` to
   `userPreviewForMessaging`, which never included `dmConversationId`.

B) Consume: Chat’s `consumePendingDmOpenPreviewIfNeeded` required
   `preview.dmConversationId`. When it was nil it cleared the pending seed
   and returned (`missing_conversation_id`). The conversation existed (or
   was created) but navigation never ran.

Fan Profile is a dedicated UIWindow overlay
(`PublicProfileOverlayWindowPresenter`), not a SwiftUI sheet. Dismiss was
already called (`onDismiss()`), but Chat dropped the pending open before
the conversation could appear. The overlay was not the primary bug; the
missing conversation id + consume guard was.

────────────────────────────────────────────────────────────────
2) FAN PROFILE MESSAGE ACTION BEFORE
────────────────────────────────────────────────────────────────
PublicProfileRedesignHero.onMessage
  → PublicUserProfilePreviewView.messageFriend(_:)

Before:
  1. Guard `isFriendActionInFlight`
  2. `startDirectConversationWithFriend(friendUserId:)`  // result discarded
  3. `refreshInboxSummaries` + `ensureSignedInSocialRealtimeIfNeeded`
  4. `pendingDmOpenPreview = userPreviewForMessaging`  // no conversation id
  5. `onDismiss()`  // overlay animates out (~320ms)
  6. Chat consume sees nil conversation id → drop pending → stay on profile
     or return to previous tab with no DM

Button was tappable. Create/fetch could succeed. Result was never consumed.

────────────────────────────────────────────────────────────────
3) CANONICAL DM HELPER REUSED
────────────────────────────────────────────────────────────────
Same path as Teams roster Message / pickup roster Message / Chat pending opens:

  ChatViewModel.startDirectConversationWithFriend
    → DirectChatService.startDirectConversation
      → RPC `start_direct_conversation` (idempotent; no duplicate rows)

  Then app-level navigation:
    pendingDmOpenPreview (with dmConversationId)
    → MainTabView selects Chat tab
    → consumePendingDmOpenPreviewIfNeeded
    → openDirectChatRoute (same helper as Friends / search / Fans Live Now)
    → DirectChatView (existing fetchExisting + startDirectConversation)

No second create path.

────────────────────────────────────────────────────────────────
4) NAVIGATION / PRESENTATION FIX
────────────────────────────────────────────────────────────────
1. Keep the returned `conversationId` and seed
   `userPreviewForMessaging(conversationId:)`.
2. Set `pendingDmOpenPreview`, clear in-flight, then `onDismiss()` so the
   overlay leaves and Chat can show the thread.
3. Consume no longer drops a pending open with a nil conversation id.
   It still prefers conversation-stable identity when the id is present;
   otherwise `openDirectChatRoute` lets DirectChatView resolve/create.

Sequence:
  Tap Message
  → canonical start/open
  → pendingDmOpenPreview with conversation id
  → dismiss Fan Profile overlay
  → Chat tab + openDirectChatRoute
  → conversation visible

No timing hacks. Existing pending-preview + overlay dismiss coordination.

Duplicate taps: `isFriendActionInFlight` still disables Message while
resolving. Failure restores the button and shows
“Couldn't open chat. Try again.” (existing copy). Profile is not a fallback.
